# Montgomery Benchmark Report

The benchmark-framework matrix was run with identical seed, data count, warm-up, iteration count, and three repetitions for the C11 reference and YASM implementation. The measurements below are short smoke/regression measurements and are not a substitute for a dedicated host-controlled performance campaign.

| Profile | C11 ST ns/call | YASM ST ns/call | Observed YASM change |
|---|---:|---:|---:|
| one | approximately 66–70 | approximately 20–25 | Faster |
| quarter | approximately 116–125 | approximately 80–83 | Faster |
| half | approximately 250–252 | approximately 203–210 | Faster |
| variable | approximately 292–318 | approximately 289–294 | Slightly faster in this sample |
| near-capacity | approximately 711–715 | approximately 706–802 | Within measurement noise in this short run |

The YASM matrix produced 30 samples across five profiles and ST/MT modes. The raw artifact was `benchmarks/reports/montgomery_asm_matrix_final_matrix.json`; the C11 comparison artifact was `benchmarks/reports/montgomery_c11_matrix_matrix.json`. The corresponding statistical summaries were generated by the pinned `benchmark_stats` tool.

The direct benchmark protocol emitted `benchmark=bignum_montgomery_mul_st` followed by `Benchmark finished.` for each successful run. The host did not provide `/usr/local/bin/perf`, so the Makefile perf-record target was not used; framework timing and JSON matrix measurements were used instead.

For a release-grade performance claim, repeat the matrix with the default workload, fixed CPU affinity, at least seven repetitions, and the same host configuration for both implementations.
